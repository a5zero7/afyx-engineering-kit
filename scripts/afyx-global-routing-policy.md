# Afyx adaptive tool routing — global

1. Start with direct source, `rg`, or focused tests for known references and local changes. Use specialists for relationships, impact, large context, or complex engineering work when they materially help.
2. Prefer a suitable Afyx capability if it is installed, healthy, fresh, and authorized on the active CLI, IDE or MCP surface. When Afyx is unavailable, use an external equivalent only if its surface and fallback are permitted. Continue with direct source if neither is suitable and report material coverage limits.
3. Preserve workspace rules, permissions and ownership. Tool availability never grants permission to install, enable, change credentials, rebuild indices, spend, or bypass a denial. Source remains authoritative.
